# Facets: Design Spec v0.1

Oct 22, 2026 · @Elvie · companion to the Project Primer

Facets (id `facets`, repo `ElvieBlooms/facets`) is the NPC mod from the primer. This spec turns the primer into concrete designs for the first build. Everything here was checked against the install Elvie uploaded: **gen1recomp 0.3.91** (`updates/gen1recomp-0.3.91.love`), its FireRed, Ruby and Emerald ROM caches, and Emerald Lens 0.3.0 from `mods/`. The primer's line numbers are from 0.3.93, so both are listed in the Reference section.

## What the install changed in the plan

Six findings change or simplify the primer's plan.

1. **Frame 9 isn't only the nurse's bow.** In FireRed/LeafGreen, 35 NPC sprites have 10 frames (the nurse plus most trainer classes: youngster, lass, hiker, swimmers and others). For trainers, frame 9 is the **VS Seeker hand raise**. `vs_seeker.lua` sets `eo.raiseHand`, `field_view.lua` 655 turns that into `a.bow`, and `pose` draws frame 9 when `frameCount > 9`. In Emerald, only the nurse has 10 frames. **Design:** a sheet can have 9 frames or the original's frame count. With 9 frames, the record says `frameCount = 9`, so the bow or hand raise shows the normal standing frame instead. No engine change, and no made-up frame.
2. **Reflections need no work in phase 1.**
   - **FireRed/LeafGreen:** NPCs have no reflection palette in the cache. Only the player's ids 0–13 do. `getReflectionDraw` returns nil for every NPC, so the engine draws no NPC reflections, with or without the mod.
   - **Ruby/Sapphire/Emerald:** the reflection is the drawn sprite, recoloured through a lookup table built from the original's palette (`field_effects_rse.lua`, `recolored`, about line 663). Colours that aren't in the table pass through unchanged, so a replaced NPC reflects in its own colours without the blue tint. That's acceptable for now; adding the tint is a later polish item.
   - **Correction to the primer:** Emerald Lens doesn't build its own reflections. They work because its art is drawn in the game's palette, so the recolour finds those colours.
3. **The folder is the mapping.** The engine's `event_objects` tables give every graphics id a name, so a sheet named `NURSE.png` maps itself. The mod needs no mapping file. The pack-number-to-name table only matters to the converter. This merges phases 1 and 2.
4. **Ruby and Emerald name some people differently.** Ruby has 30 names that Emerald lacks. 12 of them are pixel-identical Emerald sprites under a new name, and 6 more share a shape (alias table below). One `rse/` folder covers both games through a small built-in alias table.
5. **Named FireRed characters already have their own ids.** Brock, Oak, Bill, Daisy, Mr. Fuji, Celio and the others each have a unique graphics id. Mapping by name already works per character, so per-object mapping isn't needed for the first release.
6. **Other screens read the same sprites.** Wrapping `OwSprites.get` also changes the Fame Checker icons (FireRed/LeafGreen, frame 0 centred), the naming-screen icon, and the R/S/E `ow_sheet` helper. That's welcome, but the Fame Checker should be checked with 32x32 art.

Smaller corrections:

- The caches hold 152 (FireRed), 218 (Ruby) and 239 (Emerald) sprites, ids starting at 0.
- Original NPC feet sit on row 30 of the frame (one empty row at the bottom), not row 31. The converter should match that.

## Module layout

```
facets/
  manifest.json      api 2, engine_internals, games ["gen3"]
  main.lua           return function(mod) require("mods.facets.npcs").init(mod) end
  npcs.lua           finds sets, builds options, hands gen3.lua the chain
  gen3.lua           names to ids, the OwSprites.get wrap, records, caches
  names.lua          skip list, Ruby-to-Emerald aliases, option groups
  assets/npcs/<set>/meta.json
  assets/npcs/<set>/gen3/frlg/<NAME>.png
  assets/npcs/<set>/gen3/rse/<NAME>.png
  tools/npc_convert.py
  tests/             headless Lua, stubbed engine modules
```

This mirrors Emerald Lens, where `lens.lua` handles options and folders and `gen3.lua` handles the engine. `gen3.lua` keeps the same handle shape (`init(mod, ctx)` returns `{ configure = fn }`), so live option changes work the same way.

## Sprite sets and file format

- **A set** is a folder under `assets/npcs/`. `meta.json` reuses Emerald Lens's keys: `label` (option text), `credit` (list of strings), and optionally `generation`. Unknown keys are ignored.
- **File names** are the `OBJ_EVENT_GFX_` name without the prefix, upper case: `NURSE.png`, `ROCKET_F.png`, `PROF_OAK.png`.
- **Family folders:** `frlg/` covers FireRed and LeafGreen; `rse/` covers Ruby, Sapphire and Emerald. In `rse/`, a file can use either game's name, and aliases fill the gaps.
- **Sheet shape:** frames stacked vertically, one column, in `ANIM_STD` order (0–2 stand down/up/left, 3–4 walk down, 5–6 walk up, 7–8 walk left, optional 9 bow or hand raise).

**Accepted sizes**, checked per file:

| Original sprite | Frame size accepted | Frames accepted |
| --- | --- | --- |
| 16x32 person | 16x32 or 32x32 | 9, or the original's count (10 for FRLG trainers) |
| 16x16 child or tuber | 16x16 or 32x32 | 9, or the original's count |
| 32x32 (biker, cycling triathlete, Quinty Plump) | 32x32 | 9, or the original's count |
| Anything else (objects, Pokémon, boats) | not replaced in phase 1 | n/a |

- **Telling sizes apart:** a sheet as wide as the original uses the original frame height; a 32-wide sheet for a 16-wide original uses 32x32 frames. Height divided by frame height must be an accepted frame count.
- **Bad files:** anything else is logged once and falls back to the game's own sprite.

**Chain:** the selected set first, then the other sets in name order, then the game. This is Emerald Lens's fallback order, so a small "fixes" set can sit on top of a big one.

## The wrap (`gen3.lua`)

**At init**, read the running game's `event_objects` table once. Build `nameOf[id]` and `idOf[name]`, apply aliases, and drop anything on the skip list.

**On first use**, scan the chain once for each name. The result is `fileFor[id] = path`. This gives an O(1) lookup per draw, which matters because `get` runs several times per actor per frame (draw, weather mask, reflection).

```lua
local originalGet = OwSprites.get
OwSprites.get = function(graphicsId)
  local vanilla = originalGet(graphicsId)
  if not vanilla or not active then return vanilla end
  local record = built[vanilla]            -- weak-keyed by the vanilla record
  if record ~= nil then return record or vanilla end
  local path = fileFor[tonumber(graphicsId)]
  if not path then return vanilla end
  record = build(vanilla, path) or false   -- false: tried, failed, logged once
  built[vanilla] = record
  return record or vanilla
end
```

`build` works like Emerald Lens's:

- It copies every field of the original: `paletteSlot` for weather masks, `drawOffX` and `drawOffY`, `inanimate`, and the palette fields.
- It then sets `image`, `imageData`, `width`, `height`, `frameCount` and `quads[0..n-1]`.
- Keying by the original record means a cache reload (new game, save switch) rebuilds automatically, as in Emerald Lens.

**Skip list** (`names.lua`), by name, so it holds in every game:

| Family | Never replaced |
| --- | --- |
| FRLG | `RED_*`, `GREEN_*`, `BLUE`, `RS_BRENDAN`, `RS_MAY` |
| RSE | `BRENDAN_*`, `MAY_*`, `RIVAL_*`, `LINK_*`, `RED`, `LEAF` |

The players, the rival and the link/Union Room stand-ins belong to Emerald Lens or to other players. Because the two mods never share an id, each wrap passes the other's ids straight through, and load order doesn't matter.

**Live option changes** (`configure`):

- Reset `built` and `fileFor`.
- For every id that was replaced, also clear:
  - `OwSprites._reflectionLoaded[id]`
  - `package.loaded["src.core.game3.field_effects_rse"]._images[id]`, if loaded
  - `.spr` on any `OwSprites._overrides[id]`
- `OwSprites._loaded` doesn't need touching: it holds the originals, and the wrap sits after it.

**Palette overrides** (`setObjectPalette`) are used for the Deoxys rock and meteorite only, which are never replaced. Nothing to handle.

## Converter (`tools/npc_convert.py`)

Starts from Emerald Lens's `import_sheet.py` helpers (background detection, Pillow compatibility).

1. **Read** an Essentials 4x4 charset: rows down, left, right, up; columns stand, step, stand, step.
2. **Shrink** by the detected integer factor (2 for this pack) with nearest-neighbour. First check that every 2x2 block is one colour, so the shrink is lossless; warn and stop if not.
3. **Rearrange** to `ANIM_STD`:

   | Output frame | Source (row, column) |
   | --- | --- |
   | 0 stand down | (down, 0) |
   | 1 stand up | (up, 0) |
   | 2 stand left | (left, 0) |
   | 3, 4 walk down | (down, 1), (down, 3) |
   | 5, 6 walk up | (up, 1), (up, 3) |
   | 7, 8 walk left | (left, 1), (left, 3) |

   The right row is dropped, since the engine mirrors left. Which step column comes first should be copied from the working proof of concept.
4. **Line up the feet:** shift the whole sheet so the lowest solid row of the stand-down frame lands on row 30, as in the game's own sprites.
5. **Write** `<out>/gen3/frlg/<NAME>.png` and `<out>/gen3/rse/<NAME>.png`, using a recipe JSON from pack number to names. One pack sheet can feed several names (the same nurse for FRLG `NURSE` and RSE `NURSE`).
6. **Optional:** `--extra <NAME>=<png>` appends a hand-drawn frame 9 (bow or hand raise).

The recipe for Neo-Spriteman's pack is the only part that needs the pack in hand. It's data, not code, and contains no art, so it can ship.

## Tests

**Headless Lua**, with stubbed `ow_sprites`, `love.graphics` and `love.image`, and `mod.assets`:

- Unmapped id → original record, same table.
- A player, rival or link id with a file present → original record, never replaced.
- 9-frame sheet on a 10-frame original → `frameCount == 9`, and `pose(..., { bow = true })` returns frame 0.
- 32x32 sheet on a 16x16 original → width and height 32, `paletteSlot` kept.
- Wrong size → original record, one log line however many draws.
- Emerald Lens–style wrapper stacked before and after → each mod's ids come from that mod.
- `configure(nil)` → everything is the original again, reflection caches cleared for replaced ids.
- Ruby running, only `RICH_BOY.png` present → id 15 (`BOY_4`) replaced.

**In game** (FireRed first):

- Viridian Pokémon Center nurse: walk, bow (10-frame and 9-frame versions).
- A VS Seeker rematch: hand raise, or the standing fallback.
- Fame Checker icons.
- Emerald: a rain route for the weather mask, and a pond for the untinted reflection.
- Both mod load orders with Emerald Lens on.

## Proposed answers to the open questions

These are suggestions to accept or override:

- **Art bundling:** the converter runs on the player's own copy of the pack. The release has code, the recipe and the converter only. This matches the primer's no-ship rule.
- **Mapping granularity:** by name only for 1.0. Per map and object waits until someone wants variety among identical generic NPCs.
- **Options:** SET per family in 1.0, group toggles in phase 5.
- **Ruby/Sapphire/Emerald:** ship partial coverage. HGSS has most generic trainer classes and staff; Hoenn's named characters keep the game's art.
- **Field objects:** later. They're inanimate with 1–4 frames, so they need their own size rules.
- **Battle pics:** phase 7 as planned; nothing in this design blocks it.
- **meta.json:** reuse Emerald Lens's keys.
- **Name:** decided: **Facets** (id `facets`, repo `ElvieBlooms/facets`).
